# 代码库升级与迁移助手｜MySQL 数据与集成

## 持久化边界

MySQL 8.4 InnoDB 是本项目业务状态与授权关系的权威存储。租户身份进入业务唯一键与关联检查。媒体、文件、备份或模型大对象允许使用文件或对象存储，库内保存版本化引用、长度、摘要及所有者。派生缓存可从持久记录重新构建。

## 逻辑实体与事实来源

| 业务域 | 核心实体与必要字段 | 写入时必须维持的规则 |
|---|---|---|
| 仓库接入 | repo(scope,owner), snapshot(repo,commit,digest) | 获取经维护者授权的快照，白名单指定目录与可运行的测试任务，原仓库只读。 |
| 依赖盘点 | dependency(snapshot,package,locked), constraint_edge(from_pkg,to_pkg,expr) | 同时展示声明约束及锁定版本，串出阻断目标升级的最短依赖链。 |
| 影响评估 | rule(rule_key,source,range), finding(snapshot,file,line,confidence) | 解析器与模型建议区分来源，引用文件行、版本指南和测试覆盖缺口。 |
| 迁移计划 | plan(snapshot,target,rev), batch(plan,order_no,prereq) | 计划列出前置批、预期影响文件、可用验证和预算；不可解分支转人工选择。 |
| 补丁生成 | workspace(batch,base,digest), patch(batch,rev,diff_ref) | 固定输入、模型与规则版，产物限定授权目录；维护者可对任一修改给出保留或重做理由。 |
| 验证与证据 | validation(patch,toolchain,state), check_result(run,test,evidence) | 在受限环境运行已批准工具，区分环境不可用、旧版既有失败与新增回归。 |
| 审阅与采纳 | decision(patch,actor,state), export_bundle(plan,selection,digest) | 采纳以预期基线为条件，有后继时撤回先列受影响批，导出标准补丁与冲突说明。 |
| 评测与用量 | benchmark(dataset,model_rev,rule_rev), usage(run,provider,units) | 冻结保留集独立于提示调试，按任务统计真实通过率、费用与人改量；日志避免暴露私有源码。 |

## 事务、索引与对账

- **身份与约束**　工作区＋基线＋批次＋修订唯一，测试绑定补丁摘要与工具链版本。
- **业务索引**　按仓库和目标版本查计划，按批次与测试名比较基线及候选。
- **数据生命周期**　快照与日志有项目级读取和到期清理，模型端只接收授权片段。

绑定仓、基线摘要、目标版本和工具链，补丁、测试、采纳决定均关联工作区快照；基线变化重新验证。

列表使用租户、业务状态、更新时间和稳定主键分页。外部事件保留来源、外部号、内容摘要、处理结果和业务对象引用。同键不同内容产生显式冲突；网络超时后按原键查单。跨存储发布应先确认文件持久，再发布其数据库引用；回收须验证没有有效引用。

## 集成契约

只消费用户批准的项目快照、依赖清单与测试配置；导出可审查补丁和带证据的升级报告。

输入本地仓快照、目标版本、允许的目录和测试命令清单；返回升级图、阻断依赖与依据链接。

审阅选择补丁与期望基线，输出可导出的 diff、验证报告、受影响文件及撤回范围。

## 数据恢复与核验

在隔离环境恢复 MySQL 和引用清单，校验样例的源对象、派生关系及最终结果。恢复后应能回答以下问题。锁文件与建议可追溯到基线；未通过测试的批次不能标记可采纳。丢弃其中一批时保留原始项目及其他获准批次。
