# 代码库升级与迁移助手 2.0 产品需求文档

**多仓库契约升级与迁移演练**

需求评审版 · 2026-11-26 · 计划基线 v1.1.0（4cc157a）

## 产品目标与交付边界

上一版覆盖单仓快照、升级计划、补丁审阅及回归。本版支持平台团队升级共享库，定位受影响的消费者，为兼容期生成分阶段修改，在隔离环境重放契约再逐仓导出。 [项目说明](../../README.md) · [上一版业务需求](02-业务与交互-prd.md)

公开演示含一个 PHP 提供方、一个 PHP 和一个 Go 消费方。默认导出补丁，由仓库负责人决定合并。

## 使用者与工作台

平台维护者建活动，仓库负责人授予读取与导出范围，独立评审人采纳，测试负责人签演练。

活动地图按生产者到消费者展示边，定位到签名和调用文件。评审台分列代码差异、契约样例和业务回归，负责人可拒绝单块并要求重新生成。

## 功能需求

下列六项均纳入正式版本。验收编号按项目独立，后文列出每项的触发条件和预期结果。

| 需求 | 模块 | 产品行为与约束 | 验收 |
| --- | --- | --- | --- |
| R1 | 仓群登记 | 负责人导入显式授权的源码快照，统一包标识，为每仓登记负责人和允许导出范围。 | A1、A2 |
| R2 | 契约目录 | 提取 PHP 和 Go 的公开函数及 HTTP 示例契约，记录消费者调用点与证据置信度。 | A3、A4 |
| R3 | 兼容路线 | 比较双版本共存、先扩展后收缩和一次切换方案，形成有顺序的仓级波次。 | A5、A6 |
| R4 | 模型辅助修改 | 仅发送授权片段，返回候选差异及调用点解释，评审人可分块接纳或拒绝。 | A7、A8 |
| R5 | 联合演练 | 按发布前后组合运行双方契约与业务回归，归档失败响应、差异和运行环境。 | A9、A10 |
| R6 | 波次交付 | 向负责人导出每仓补丁和撤回说明，按实际回执推进，漂移时重新定位差异。 | A11、A12 |

## 页面操作与回执

| 关联需求 | 角色与入口 | 操作细节 | 需要读回的字段 |
| --- | --- | --- | --- |
| R1 · 仓群登记 | 仓库负责人/授权目录 | 确认快照、许可的目录和允许向模型提供的上下文 | snapshot_id、allowed_paths |
| R2 · 契约目录 | 接口维护者/影响地图 | 展开某次 API 修改对应的消费者，标记动态调用 | symbol_id、consumer_edges |
| R3 · 兼容路线 | 平台维护者/活动排程 | 指定扩展期及移除条件，冻结消费端组合 | campaign_rev、wave_order |
| R4 · 模型辅助修改 | 代码评审人/差异对照 | 逐块比较建议与基线并附理由，可回滚选中块 | candidate_hash、accepted_hunks |
| R5 · 联合演练 | 测试负责人/联合验证 | 执行消费方和提供方组合，分类测试失败或环境失败 | matrix_id、failed_pairs |

每个测试矩阵保存工作区镜像、依赖锁、命令、退出码和产物摘要。拒绝运行、缺依赖和超时各自计数。未经审阅而采纳的补丁数必须为零。

## 状态、权限与数据

活动 盘点→冻结→波次预演→部分采纳→已交付。基线漂移转待重算，未采纳候选可丢弃。

源码快照只读。验证运行在显式授权的隔离环境，默认无外部凭据。模型输入与补丁按仓权限裁剪。

MySQL 保存业务记录与操作回执。下列为新增逻辑对象和关键字段，所有归属组织的数据都须持有可校验的组织标识。

- `estate_repo(snapshot,owner)`
- `contract_symbol(producer,version)`
- `consumer_edge(symbol,callsite)`
- `campaign_wave(repos,base_hashes)`
- `attestation(test_id,input_hash,result)`

契约快照按生产者提交与符号身份唯一，矩阵结果固定两个消费端及提供端的源码摘要。 写入前校验操作者对目标对象的权限与当前修订。详情、搜索、导出和后台重试按同一归属校验。保留决定者、请求号、前后状态、发生时间及关联证据编号。

## 核心接口与集成

主要写入入口为 `POST /migration-campaigns/{id}/rehearsals`。请求必填字段为 `wave_id, repo_digests, contract_set, runner_profile`。成功回执提供 rehearsal_id, matrix, evidence_refs。请求另带租户身份和幂等键。相同键及相同内容返回原业务编号，相同键对应不同内容返回 409。输入不满足业务约束时返回 422 和字段路径，身份无权限读取的跨租户对象返回 404。

需要异步处理时，接收事务同时写入业务记录与待处理事件，再返回 202 及回执查询地址。回读须显示当前状态、已完成步骤、上次失败原因和可重试条件。外部系统已受理但应答丢失时，按原请求身份核查实际结果。

### 合成请求与业务回执样例

请求体示例使用演练环境中的对象。带摘要的样例在开发验收时应替换为实际文件或参数的计算值。

```json
{
  "wave_id": "W2",
  "repo_digests": [
    "sha256:bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb",
    "sha256:cccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccc"
  ],
  "contract_set": "C1",
  "runner_profile": "isolated-local"
}
```

业务回执示例可由提交响应或后续状态查询取得。

```json
{
  "rehearsal_id": "R2",
  "matrix": "M2",
  "evidence_refs": []
}
```

任一快照缺少该运行器的授权时返回 403，在读取源码前结束请求。

## 升级、部署与恢复

单仓计划可作为一次只含一个仓库的活动导入，已有采纳记录保留原审阅人与源码摘要。 在隔离副本运行迁移预检，输出记录数量、归属冲突和待处理编号。新增结构先部署，回填分批提交并保存游标，完成对账后按租户启用新入口。

演练时在首次成功写入新业务后中断进程，从检查点重启。核对基线提交、锁文件、测试产物摘要及采纳清单。需要退出试点时停收新请求，排空已受理操作并导出未决清单。涉及数据恢复时同时恢复数据库与关联证据，再核对外部已生效的动作。

## 编号验收用例

以下均为下一版待执行的验收条件。正常与异常场景使用隔离租户、固定时钟和可重置的合成数据。

| 编号 | 需求 | 操作与可观察结果 |
| --- | --- | --- |
| A1 | R1 · 仓群登记 | 两个仓同名包按来源与版本区分。 |
| A2 | R1 · 仓群登记 | 快照缺授权的仓只显示待接入，不读取源码。 |
| A3 | R2 · 契约目录 | 删除一个必填字段可列出依赖该字段的消费者及样例。 |
| A4 | R2 · 契约目录 | 动态调用无法解析时标记待人工确认。 |
| A5 | R3 · 兼容路线 | 先发布兼容库再升级两个消费者，最后移除旧入口。 |
| A6 | R3 · 兼容路线 | 消费者仍使用旧入口时禁止关闭兼容期。 |
| A7 | R4 · 模型辅助修改 | 真实本地模型对未预录的调用给出候选并能回溯输入摘要。 |
| A8 | R4 · 模型辅助修改 | 越出仓范围的修改被拒，模型耗时与用量仍记录。 |
| A9 | R5 · 联合演练 | 旧消费者配新兼容库及新消费者配新库均通过才放行。 |
| A10 | R5 · 联合演练 | 依赖下载失败记执行错误且不算验证通过。 |
| A11 | R6 · 波次交付 | 第二仓偏离基线时第一仓已批准的回执仍可回读。 |
| A12 | R6 · 波次交付 | 部分失败只重跑失败仓，已通过仓的证据沿用冻结版本。 |
| A13 | 全流程 | 冻结 20 个跨仓变更，分别报告纯规则与实际本地模型的有效补丁数、业务回归通过数、拒绝数及 token。至少包含 5 个必须保留旧行为的反例。 |
| A14 | 容量与可靠性 | 50 仓、5 万个索引符号，变更一个共享包后影响分析 ≤ 60 秒，报告记录无法解析的调用数。 |

负载报告须记录机器及依赖版本、预热和采样时长、成功数、拒绝数和超时数。验收人从工作台与业务记录两侧核对 A13，并附上原始输入、回执和最终状态。真实模型、人工判断和回放夹具分别出具结果，记录模型及权重版本、输入规模、失败样本与资源消耗。

### A13 模型评测

每个样本预先标出允许变更的调用、必须保留的行为及回归命令。补丁通过率以全部 20 例为分母，另列可自动处理的子集。必须保留行为的反例不得通过采纳门槛。

## 分期交付

1. **跨仓依赖与契约。** 交付可导入的样例和可读回的第一批业务对象，验证基础身份、归属及版本。
2. **迁移路线与候选。** 串通参与角色和执行入口，演练并发、重复请求及部分成功后的恢复。
3. **联合验证和分仓交付。** 完成全流程验收、容量实测和旧版升级。随开源发行提供中文配置、样例输入输出、备份恢复步骤及已知限制。
