# 代码库升级与迁移助手｜开源项目说明与首个案例

**upgrade-agent** 是面向自托管的 Go 项目。面向合法维护的自有项目，首个语言适配器为 PHP Composer，真实推理由可替换模型提供。 本页作为后续公开使用手册的需求稿，实际发行时补入测试版本、安装入口与已验证的依赖组合。

## 准备

原创旧版 PHP 样例、固定依赖清单、可替换模型端与隔离工作区。

原创 Laravel 样例含两个依赖冲突、一个弃用调用与一个业务回归；把升级拆成依赖、调用替换两批。

## 第一次使用

1. 导入原创旧版框架项目及固定锁文件，选择升级目标，先运行基线测试。
2. 查看阻断依赖链和弃用位置，批准两个独立计划批次的可写路径与测试范围。
3. 在隔离工作区生成候选，保留一个出现业务回归的版本，对照基线检查失败证据。
4. 修复后复跑，逐批采纳或拒绝，在新检出目录应用导出补丁并核对最终锁文件摘要。

## 对照综合样例

锁文件与建议可追溯到基线；未通过测试的批次不能标记可采纳。丢弃其中一批时保留原始项目及其他获准批次。 对照结果时保留源记录号、版本和操作时间，追踪从输入到最终交付的关联。

## 制造一次可恢复的异常

尝试修改无关配置的补丁进入拒绝清单。回到对象详情核对 workspace 和审计记录，再按指定版本恢复或重试。确认相同操作不会生成两份有效结果。

## 自托管与反馈

测试仅执行项目维护者批准的既有任务。网络及凭据按工作区最小授权；模型意见缺证时标记待核。 提交问题请提供版本、最小合成输入、预期与实际结果。对接扩展可从以下方向开始：语言规则、依赖求解器与模型适配器；每项弃用规则附正反例和适用版本。
